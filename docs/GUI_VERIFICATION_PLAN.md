## Этап 0 — «Живое окно» (≈3 мин, без CLI)

Цель: убедиться, что GUI отвечает и сеть OKX доступна.

| # | Где | Что нажать | Что должно быть |
|---|-----|------------|-----------------|
| 0.1 | **График** | Открыть вкладку | График сам грузится (Live), статус «OKX: N свечей…» |
| 0.2 | **График** | Источник **OKX** | Свечи, прокрутка колёсиком влево — история |
| 0.3 | **График** | Подвкладка **Решение** | Карточка «Решение» — направление, P(up), модели (или «Загрузка» → данные) |
| 0.4 | **График** | Источник **IST (локально)** | Если есть parquet+bundle — свечи, фон regime, опционально сигналы |
| 0.5 | **Режим** | Вкладка **Режим** → **Загрузить** | Таблица баров, % trend/range в статистике |
| 0.6 | Toolbar | **Обновить** | Статусная строка: `График — BTC/USDT 1h` (или текущая вкладка) |

**Не ок, если:** OKX «Ошибка» без demo — проверьте интернет; IST «Нет локальных данных» — нет parquet (этап 2).

## Этап 2 — Pipeline: данные и модели (≈30–120 мин, реальное время)

Цель: зелёный чеклист, bundle, журнал WFO.

Вкладка **Задачи** → подвкладка **Pipeline**.

| # | Кнопка | Когда | Ожидание после успеха (код 0 в логе CLI) |
|---|--------|-------|------------------------------------------|
| 2.1 | **Подготовить символ** | Нет OHLCV | Data health: rows > 0; чеклист: ohlcv ✓ |
| 2.2 | ☑ **Перекачать OHLCV** | Нужны свежие свечи с биржи | То же + download в логе |
| 2.3 | **Признаки** | OHLCV есть | features ✓; Data health features |
| 2.4 | **Тюнинг thesis** | Нужен shortlist (долго) | Запись в журнале; stdout в логе CLI |
| 2.5 | **Финальное обучение** | После tune или с ☑ tuning-best | bundle ✓; toolbar: run_id модели |
| 2.6 | **Отчёт WFO** | Есть bundle + features | ☑ кэш фичей, ☑ tuning-best; `max_rows` при необходимости |

**Во время CLI:** смотрите верхний **«Лог CLI»** (stdout), не путать с нижним **логом prepare-symbol (JSONL)**.

**После «Отчёт WFO»:**

| # | Где | Действие | Ожидание |
|---|-----|----------|----------|
| 2.7 | Toolbar | acc: **PASS** или **FAIL** | Из последнего run в журнале |
| 2.8 | **Задачи** → **Журнал WFO** | **Обновить** | Новая строка в таблице |
| 2.9 | **Журнал** | Клик по строке | Вкладки **Сводка** (метрики + checks) и **JSON** |
| 2.10 | **Журнал** | **Лучший PASS** | Выделяется лучший acceptance run для пары |
| 2.11 | **График** | IST + ☑ Сигналы | Маркеры на хвосте, meta P(up) снизу |

## Этап 3 — Согласованность «решение ↔ paper ↔ бэктест» (≈10 мин)

Цель: одна логика сигнала на последнем баре.

| # | Где | Действие | Ожидание |
|---|-----|----------|----------|
| 3.1 | **График** → **Решение** | Запомнить: signal, P(up), «Блокировка» | Напр. FLAT + dead-zone |
| 3.2 | **Задачи** → **Paper** | **Подключить paper** | «Подключено (paper)», баланс 10000 USDT |
| 3.3 | **Paper** | Режим **Вручную** (не Авто 30/60) | Сам шаги не идут |
| 3.4 | **Paper** | **Выполнить шаг** | Строка в логе шага; график **Баланс по шагам** +1 точка |
| 3.5 | **Paper** | Блок сверки внизу | Текст «Сверка Paper vs Backtester» |

**Как читать сверку:**

| Ситуация | Значение |
|----------|----------|
| Сигнал 0, dead-zone | Нормально: Paper и Backtester оба FLAT, net 0% |
| Сигнал ±1, qty > 0 | Paper торговал; Backtester — доходность со shift(1) |
| «Short not supported» | В paper нет шорта без позиции — ожидаемо |

| 3.6 | **Paper** | **Серия шагов** ×5 | Несколько точек на графике баланса |
| 3.7 | **Paper** | **Сброс портфеля** / **Отключить** | Сброс состояния |

## Быстрый чеклист «всё работает»

Отметьте галочкой:

- [ ] OKX график live обновляется (статус «обновлено HH:MM:SS»)
- [ ] IST график с bundle (сигналы/regime)
- [ ] **Решение**: 4 модели, направление, блокировка понятна
- [ ] **Режим**: таблица загружается
- [ ] **Bundle**: manifest, lgb/gru/xgb/cnn
- [ ] Pipeline: ohlcv → features → bundle (хотя бы без полного tune)
- [ ] **Отчёт WFO** → строка в **Журнале**
- [ ] Toolbar **acc:PASS** (цель диплома) или осознанный FAIL с причиной в сводке
- [ ] **Paper**: шаг + сверка + график баланса
- [ ] **Сохранить** конфиг → перечитывается

## Если что-то не так

| Симптом | Куда смотреть | Что сделать |
|---------|--------------|-------------|
| CLI кнопки серые | Запущен `--demo` | Перезапуск без `--demo` |
| Нет bundle | **Задачи** → Pipeline | **Финальное обучение** |
| IST пустой | **График** IST | Сначала **Признаки**, проверить parquet |
| Всегда FLAT в Paper | **Решение** / **Конфигурация** | Уменьшить `min_signal_margin` или смотреть P(up) |
| Журнал пустой | **Журнал** → Обновить | Сначала **Отчёт WFO** |
| acc:FAIL | **Журнал** → Сводка | Какой check ✗ (WFE, Sharpe…) |
| Баланс paper не рисуется | **Paper** | Только **Выполнить шаг**; перезапуск GUI после патча |
| Шаги сами в Paper | Combo **Вручную** | Выключить «Авто 30/60 с» |

## Порядок для защиты диплома (≈15 мин показ)

1. Toolbar: BTC 1h, bundle, acc.  
2. **График** OKX live → IST с сигналами.  
3. **Решение**: LONG/SHORT/FLAT и шаги pipeline.  
4. **Задачи** → **Журнал**: лучший run, сводка acceptance.  
5. **Конфигурация**: пороги + эталон 4 model.  
6. (Опционально) **Paper**: один шаг + сверка «оба FLAT или согласны».
