# 3.1 Постановка практического эксперимента

Практический эксперимент представляет собой эмпирическое исследование разработанной интеллектуальной торговой системы (далее — ИТС) на исторических котировках криптовалютного рынка. Ниже приводятся цель, объект, параметры и схема проведения эксперимента.

## 3.1.1. Цель эксперимента

Целью практического эксперимента является верификация предложенных методов прогнозирования и принятия торговых решений в условиях, приближённых к реальной торговле. В соответствии с поставленной целью формулируются следующие исследовательские задачи:

1. оценить эффективность адаптивного ансамбля моделей (adaptive ensemble) по сравнению с базовыми предикторами на выборках вне обучающего периода (out-of-sample, OOS);
2. проанализировать влияние динамического взвешивания (dynamic weighting) прогнозов отдельных моделей в зависимости от выявленного рыночного режима;
3. выполнить сравнительный анализ одиночных моделей (single models) и их ансамблевого объединения (ensemble);
4. исследовать устойчивость системы при скользящей валидации (walk-forward), с учётом транзакционных издержек и критериев приёмки результатов тестирования на исторических данных (backtesting).

Решение перечисленных задач позволяет сделать выводы о применимости разработанной архитектуры ИТС и о вкладе отдельных компонентов (режимная адаптация, мета-взвешивание, конвейер сигналов) в итоговые показатели стратегии.

## 3.1.2. Объект исследования

**Объектом исследования** выступает процесс прогнозирования направления изменения цены финансового инструмента и формирования дискретных торговых решений на основе методов машинного обучения и ансамблевого объединения моделей.

Объект исследования конкретизируется следующим образом:

| Характеристика | Содержание |
|----------------|------------|
| Рынок | Криптовалютный рынок (спотовый сегмент, централизованная биржа) |
| Торговый инструмент | Пара BTC/USDT |
| Исходные данные | Временные ряды котировок формата OHLCV (цена открытия, максимум, минимум, закрытия, объём) |
| Представление данных | Мультитаймфреймовый набор признаков, полученный после синхронизации рядов и этапа инженерии признаков (feature engineering) |

Таким образом, эксперимент ориентирован на высоколиквидный цифровой актив с непрерывной торговлей и доступной историей тиковых агрегатов в виде свечных интервалов.

## 3.1.3. Параметры эксперимента

### Постановочные параметры

Основные параметры практического эксперимента сведены в табл. 3.1.

**Таблица 3.1 — Параметры практического эксперимента**

| Параметр | Значение |
|----------|----------|
| Биржа | OKX |
| Торговый инструмент | BTC/USDT |
| Таймфреймы | 5m, 15m, 1h |
| Период наблюдений | 2022–2025 гг. |
| Горизонт прогнозирования | 1 свеча |

Указанные параметры определяют пространство исходных данных и масштаб временного горизонта прогноза на этапе постановки эксперимента.

### Программная конфигурация ИТС

Верификация системы выполняется на программной реализации ИТС; параметры эксперимента задаются конфигурационными файлами. Ниже приведены фрагменты конфигурации, отражающие источник данных, состав моделей, режим ансамбля и параметры имитации торговли.

Фрагмент корневого файла конфигурации (`config.yaml`):

```yaml
data_layer:
  connectors:
    okx:
      api_key: ${OKX_API_KEY}
      base_url: https://www.okx.cab/api/v5
      passphrase: ${OKX_PASSPHRASE}
      rate_limit: 20
      sandbox: true
      secret_key: ${OKX_SECRET_KEY}

orchestration:
  ensemble_mode: regime_adaptive
  model_keys:
    - lgb
    - gru
    - xgb
    - cnn
  prediction_horizon: 12
  trend_weights:
    lgb: 0.10
    gru: 0.45
    xgb: 0.10
    cnn: 0.35
  range_weights:
    lgb: 0.55
    gru: 0.10
    xgb: 0.25
    cnn: 0.10

backtesting:
  walk_forward:
    train_window: 252
    validation_window: 63
    test_window: 63
    step_size: 21
  simulation:
    commission: 0.0006
    slippage: 0.0002
```

Профиль торгового инструмента (`config/symbols/BTC-USDT_1h.yaml`):

```yaml
symbol: BTC-USDT
timeframe: 1h

orchestration_tuning_best:
  profile: canonical_4model
  config_path: config/profiles/canonical_4model.yaml
  ensemble_mode: regime_adaptive
  signal_strategy: ensemble
  model_keys:
    - lgb
    - gru
    - xgb
    - cnn
  prediction_horizon: 12
  train_window_size: 1500
  test_window_size: 250
  walk_forward_step: 250
```

Исследовательский профиль четырёхмодельного ансамбля (`config/profiles/canonical_4model.yaml`):

```yaml
data_collection:
  start_date: "2022-01-01 00:00:00"
  end_date: null

synchronization:
  base_timeframe: "1h"
  auxiliary_timeframes:
    - "15m"
    - "4h"
  resample_rule: "1h"
  fill_method: ffill

orchestration:
  ensemble_mode: regime_adaptive
  model_keys: [lgb, gru, xgb, cnn]
  prediction_horizon: 12
  train_window_size: 1500
  test_window_size: 250
  walk_forward_step: 250
```

Сопоставление постановочных и программных параметров показывает следующее. В каноническом профиле в качестве базового таймфрейма используется интервал 1h, вспомогательные ряды — 15m и 4h; начало выборки зафиксировано с 01.01.2022. Горизонт прогнозирования в конфигурации оркестрации задан как `prediction_horizon: 12` (двенадцать базовых свечей). Интервал 5m и горизонт «одна свеча» относятся к расширенным постановкам мультитаймфреймового анализа и могут быть воспроизведены средствами подсистемы загрузки и синхронизации данных без изменения общей архитектуры эксперимента.

На рис. 3.1 (при оформлении дипломной работы) рекомендуется разместить иллюстрацию фрагмента файла `config/profiles/canonical_4model.yaml` с видимыми полями `data_collection`, `synchronization` и `orchestration`.

## 3.1.4. Схема эксперимента

Эксперимент организован как последовательный вычислительный конвейер: от накопления исторических котировок до расчёта показателей эффективности стратегии на OOS-выборках. Обобщённая схема представлена на рис. 3.2.

**Рисунок 3.2 — Схема практического эксперимента**

```
Исторические данные
        │
        ▼
Инженерия признаков
        │
        ▼
      Модели
        │
        ▼
     Ансамбль
        │
        ▼
Торговые сигналы
        │
        ▼
  Тестирование на истории
        │
        ▼
    Метрики
```

Эквивалентная блок-схема в нотации Mermaid (для генерации рисунка в редакторе):

```mermaid
flowchart LR
    A["Исторические данные<br/>OHLCV, BTC/USDT, OKX"] --> B["Инженерия признаков<br/>индикаторы, MTF-синхронизация"]
    B --> C["Модели<br/>LGB, XGB, GRU, CNN"]
    C --> D["Ансамбль<br/>режимно-адаптивное взвешивание"]
    D --> E["Торговые сигналы<br/>конвейер принятия решений"]
    E --> F["Backtesting<br/>walk-forward, OOS"]
    F --> G["Метрики<br/>Sharpe, PF, MDD, WFE"]
```

Содержательная характеристика этапов схемы приведена в табл. 3.2.

**Таблица 3.2 — Этапы практического эксперимента**

| № | Этап | Содержание |
|---|------|------------|
| 1 | Исторические данные | Загрузка рядов OHLCV с биржи OKX, хранение в формате Parquet |
| 2 | Инженерия признаков | Расчёт технических индикаторов (EMA, RSI, MACD, ATR, ADX), согласование вспомогательных таймфреймов с базовой сеткой 1h |
| 3 | Модели | Обучение и применение четырёх предикторов (градиентный бустинг, рекуррентная и свёрточная нейросети) на скользящем окне |
| 4 | Ансамбль | Объединение прогнозов с динамическими весами в режимах «тренд» и «флэт» (trend / range) |
| 5 | Торговые сигналы | Пороговая фильтрация направления, мета-разметка (meta-labeling), ограничение риска |
| 6 | Тестирование на истории | Walk-forward-валидация с учётом комиссии (0,06 %) и проскальзывания (0,02 %) |
| 7 | Метрики | Расчёт коэффициента Шарпа, profit factor, максимальной просадки, walk-forward efficiency (WFE) и иных критериев приёмки |

Представленная схема обеспечивает воспроизводимость эксперимента: каждый этап соответствует выделенному модулю ИТС и фиксируется конфигурационными параметрами и журналом прогонов (backtest journal).
